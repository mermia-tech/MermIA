# MR-23: Parsers for "Ventas por día" and "Recetas" (plan)

Status: draft, waiting for go-ahead. Branch `MR-23-parsers-2-3`.

## Goal
Two registered, pure xlsx parsers that each produce a valid `NormalizedBatch`:
- `sr.ventas_por_dia@v1` -> `daily` batch (name already used by the fixture generator and seed batches).
- `sr.recetas@v1` -> `catalog` batch.

Each has a golden test. Layouts are provisional (SR 8 manual) until the pilot sends real files (MR-5).

Out of scope: Corte Z (goes with MR-39), "Recetas – Insumos elaborados" (sub-recipes), loading recipe batches into `pending_change`.

## PR A: Ventas por día (~380 lines, ~1 day)
1. Move the shared title-block helpers (period line "Del … al …", date reader, location hint) from `parsers/sr_productos_vendidos.py` to `parsers/_sr_common.py`. No behaviour change; the existing 35 tests must still pass.
2. `parsers/sr_ventas_por_dia.py`:
   - Fingerprint: title "ventas por dia" plus a header row with Fecha and Venta neta.
   - Find columns by name, not position. 01 §3 lists food / beverages / other / courtesies; the synthetic file adds payment, tip, guest and cancellation columns.
   - Fecha and Venta neta are required. A missing optional column stays `None` (`{}` for the payment mix): not reported is not zero.
   - Column mapping:

     | Report column | Field |
     |---|---|
     | Cuentas | `tickets` |
     | Personas | `guests` |
     | Descuentos | `discounts` |
     | IVA | `tax` |
     | Propinas | `tips` |
     | Efectivo / Tarjeta / Transferencia (/ Vales / Otros) | `payment_mix` |
     | Cancelaciones | `cancellations_count` |
     | Importe cancelado | `cancellations_amount` |

   - Accept dates as `dd/mm/yyyy` text or as Excel date cells.
   - `MalformedReport` for a repeated date or a date outside the period.
   - The Total row is optional. If present it becomes `totals`; if absent, totals are the sum of the rows.
   - Warnings only (no rejection) when Alimentos + Bebidas (+ Otros) − Descuentos ≠ Venta neta, or the payment mix ≠ Venta neta.
3. `registry.py`: add a second `XlsxParser` entry.
4. Tests:
   - New `tests/ingestion/test_golden.py` runs every `fixtures/sr/*/*.xlsx` against its `.golden.json`, so pilot files are picked up automatically. It replaces the Productos-only golden test.
   - New `test_sr_ventas_por_dia.py`: small report, missing optional columns, a Total row that matches and one that doesn't, Excel date cells, duplicate dates, warnings, wrong-file cases.
   - Fix `test_another_sr_report_is_not_recognized`. It uses the Ventas file to expect `UnknownReport`, which will break; point it at a made-up report and update the known-reports message assertion.

## PR B: Recetas (~470 lines, ~1 day; split out the fixture generator if it needs to shrink)
5. Fixture generator (`packages/fixtures/src/mermia_fixtures/emit.py` plus `tests/test_fixtures.py`):
   - Emit `recetas_L1_<date>.xlsx` and its golden from the 15 seeded recipes.
   - Provisional flat layout, one row per recipe line: `Clave | Producto | Clave insumo | Insumo | Cantidad | Unidad | Rendimiento % | Costo`, titled "Recetas - Productos", with a date line.
   - Regenerate with `uv run python -m mermia_fixtures`.
6. `parsers/sr_recetas.py`:
   - Group rows by product into `RecipeIn` and `RecipeLineIn` with `yield_qty` = 1.
   - Convert units to base units in the parser (kg->g, l->ml; g/ml/pza pass through), because the MR-25 engine does no conversion. An unknown unit is an error that sends the batch to `needs_review`.
   - Refuse a quantity ≤ 0 (`pending.RecipeLine` requires > 0) and duplicate (product, ingredient) pairs.
   - Read Costo but don't emit it; the contract has no field for it.
7. Register the parser and add `test_sr_recetas.py`: units, unknown unit, quantity ≤ 0, missing date, grouping, Costo ignored.
