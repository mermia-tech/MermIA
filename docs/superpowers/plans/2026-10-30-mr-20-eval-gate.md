# MR-20 Eval Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the MR-18 harness into a gate report (per model and per category, with tone), run a cheap preliminary exam (4 low-cost models x 40 cases x 1 run, under US$1), and write a provisional model decision in `docs/decisions/llm.md`.

**Architecture:** The CLI keeps running every case on every model, but now keeps one `ScoredRun` per run. A pure `gate` module aggregates the runs into pass / fail rows against the §H3 thresholds; a `judge` module adds the tone score with a second Agno agent and no tools. Every run is dumped to JSON so a model can be rerun alone and the dumps merged, and so the human can review 10 sampled replies.

**Tech Stack:** Python 3.12, uv, Agno 3.1.6, pytest, mypy strict, ruff (line 100).

**Spec:** `docs/superpowers/specs/2026-10-30-mr-20-eval-gate-design.md`

## Global Constraints

- Thresholds (copy exactly): tool >= 0.95; args >= 0.95; numbers == 1.0; tone mean >= 4.0 and tone min >= 3; p50 <= 3.0 s; p95 <= 8.0 s; mean cost <= US$0.003 per question; errors <= 5 % of runs (spec: "high error rate not eligible").
- Errored runs are never scored; they count only in `errors`.
- Judges (cheap for now): primary `google:gemini-3.8-flash`; cross judge `openai:gpt-5.6-luna` on runs whose model has the judge's provider prefix. For those runs the gate uses `min(primary, cross)`. The final run switches them to Sonnet 5.5 / GPT-6.1 Sol by editing the two constants.
- Budget: `openai:gpt-6.1-sol` and `anthropic:claude-sonnet-5-5` move to `PAUSED` in `config.py`; `--models` rejects them. The preliminary run is `--runs 1` on the 4 models left in `MODELS`.
- Same `SYSTEM_PROMPT` and `tool_definitions()` for every model. Each dump records `tools_sha256()` and `git rev-parse HEAD`.
- Backward compatible: without `--judge` the harness behaves as today plus the gate report (tone shown as `-`, not measured).
- Run dumps live in `apps/eval/out/` (git-ignored); they contain replies to mock data only.
- Never print `.env` values. Commits: `MR-20: <what changed>`, ending with the `Co-Authored-By` line.
- Code and docs in English; the judge rubric judges Mexican Spanish.

## Review Focus

- A model whose every run errored: the gate row shows `-`, fails, and nothing divides by zero (test in Task 1).
- The judge answers prose around the JSON, or a score outside 1-5: the JSON is extracted if present, otherwise the tone is missing for that run and the tone check fails as "incomplete" (tests in Task 2).
- The 1-2 h run dies halfway (Ctrl-C, crash): the dump of the runs done so far is still written (test in Task 3).
- A model is rerun alone after a flaky provider: merging dumps replaces that model's runs instead of doubling them (test in Task 1).
- A model with no price: the cost check fails as `n/a`, not a crash (test in Task 1).

### Task 1: Gate report (`gate.py`)

**Files:**
- Create: `apps/eval/src/mermia_eval/gate.py`
- Test: `apps/eval/tests/test_gate.py`

**Interfaces:**
- Produces:
  - `@dataclass ScoredRun`: `model: str`, `case_id: str`, `category: str`, `question: str`, `reply: str`, `calls: list[dict[str, Any]]`, `scores: dict[str, float] | None` (keys `tool`, `args`, `numbers`; `None` when errored), `tone: int | None`, `tone_cross: int | None`, `tone_reason: str`, `seconds: float`, `cost: float | None`, `error: str | None`. Property `tone_gate -> int | None`: `min` of the non-None of `tone`, `tone_cross`; `None` if both are `None`.
  - `THRESHOLDS: Final` dict with the values of Global Constraints.
  - `percentile(values: Sequence[float], q: float) -> float`: nearest rank, `sorted(values)[ceil(q * n) - 1]`.
  - `@dataclass GateRow`: `model`, `category` (`"all"` or a category), `tool`, `args`, `numbers`, `tone_mean`, `tone_min`, `p50`, `p95`, `cost` (all `float | None`), `runs: int`, `errors: int`, `checks: dict[str, bool]`; property `passed -> bool` = all checks.
  - `gate_rows(runs: Sequence[ScoredRun]) -> list[GateRow]`: per model one `"all"` row, then one row per category in the order of `Category`.
  - `format_gate(rows: Sequence[GateRow]) -> str`: a fixed-width table like `format_table`, `-` for `None`, `n/a` for missing cost, a final column `PASS` / `fail: tool,p95,...`.
  - `write_dump(path: Path, runs: Sequence[ScoredRun], meta: Mapping[str, str]) -> None` and `load_dumps(paths: Sequence[Path]) -> list[ScoredRun]` (JSON `{"meta": ..., "runs": [...]}`; a model present in a later file replaces all its runs from earlier files).
  - `main(argv)` for `python -m mermia_eval.gate out/a.json out/b.json`: prints `format_gate(gate_rows(load_dumps(...)))`.

- [ ] **Step 1: Write the failing tests** in `apps/eval/tests/test_gate.py`, building `ScoredRun`s with a small helper:
  - `test_percentile_nearest_rank`: `percentile(range(1, 21), 0.5) == 10`, `percentile(range(1, 21), 0.95) == 19`, `percentile([4.0], 0.95) == 4.0`.
  - `test_all_pass`: 3 runs, scores all 1.0, tone 5, seconds 1.0, cost 0.001 → the `"all"` row has `passed is True`.
  - `test_each_threshold_fails_alone`: parametrized over (field change → failing check): tool 0.9 → `tool`; numbers 0.0 on one of 3 runs → `numbers`; tone 3 on all → `tone_mean`; tone 2 on one → `tone_min`; seconds `[1,1,9]` → `p95`; cost 0.004 → `cost`.
  - `test_errors_not_scored_and_counted`: 1 errored run (scores None) + 19 ok runs → tool mean from the 19 only, `errors == 1`, `checks["errors"] is True`; 2 of 20 errored → `checks["errors"] is False`.
  - `test_every_run_errored`: all errored → numeric fields `None`, `passed is False`, no exception.
  - `test_missing_price_fails_cost`: one run with `cost=None` → row `cost is None`, `checks["cost"] is False`, and `format_gate` shows `n/a`.
  - `test_no_tone_is_not_measured`: tone None everywhere → `tone_mean is None`, `checks["tone_mean"] is False`; one run with tone None among judged runs → also False ("incomplete").
  - `test_tone_gate_uses_lower_judge`: `tone=5, tone_cross=3` → `tone_gate == 3`.
  - `test_rows_per_category`: runs in `sales` and `writes` → rows `all`, `sales`, `writes` in that order for the model.
  - `test_dump_roundtrip_and_model_replacement` (tmp_path): file A has models X and Y, file B has model Y only → `load_dumps([A, B])` keeps X from A and only B's Y runs.

### Task 2: Tone judge (`judge.py`)

**Files:**
- Create: `apps/eval/src/mermia_eval/judge.py`
- Test: `apps/eval/tests/test_judge.py`

**Interfaces:**
- Consumes: `build_model(spec_id)` from `config.py`.
- Produces:
  - `JUDGE: Final = "google:gemini-3.8-flash"`, `CROSS_JUDGE: Final = "openai:gpt-5.6-luna"`.
  - `needs_cross(model: str, judge: str = JUDGE) -> bool`: same provider prefix (text before `:`).
  - `JUDGE_PROMPT: Final[str]`: the rubric. Score 1-5 on: Mexican register (not Spain, not neutral-corporate); one form of address kept (tú or usted, not mixed); concise (an owner reads it on WhatsApp); no anglicisms where common Spanish exists; at most one emoji. Do not judge whether the figures are right. Answer only `{"score": <1-5>, "reason": "<one line>"}`.
  - `parse_verdict(text: str) -> tuple[int, str]`: takes the first `{...}` in the text, `json.loads`, requires an int `score` in 1..5; raises `ValueError` otherwise.
  - `judge_tone(judge: str, question: str, reply: str, agent_factory: Callable[..., Any] = Agent) -> tuple[int | None, str]`: an agent with no tools and `instructions=JUDGE_PROMPT`, asked with the question and the reply; returns `(None, "<error>")` on a provider error or a `ValueError`, never raises.

- [ ] **Step 1: Write the failing tests** (fake agent factory as in `test_run.py`):
  - `test_parse_plain_json`: `'{"score": 4, "reason": "ok"}'` → `(4, "ok")`.
  - `test_parse_json_inside_prose`: `'Claro.\n{"score": 5, "reason": "bien"}\nSaludos'` → `(5, "bien")`.
  - `test_parse_rejects`: parametrized `'{"score": 0}'`, `'{"score": 6}'`, `'{"score": "4"}'`, `'sin json'` → `ValueError`.
  - `test_judge_tone_ok`: fake agent returning the plain JSON → `(4, "ok")`, and the prompt it got contains both the question and the reply.
  - `test_judge_tone_never_raises`: factory raising `RuntimeError("boom")` → `(None, ...)` containing `boom`; fake returning `"no sé"` → `(None, ...)`.
  - `test_rubric_names_the_criteria`: `JUDGE_PROMPT` mentions `tú`, `usted`, `emoji` and the JSON shape.
  - `test_needs_cross`: `needs_cross("google:gemini-3.5-flash-lite")` is True; `"openai:gpt-5.6-luna"` and `"anthropic:claude-haiku-5-5"` are False.

- [ ] **Step 2: Run them to see them fail**

Run: `uv run pytest apps/eval/tests/test_judge.py -q`
Expected: FAIL, module not found.

- [ ] **Step 3: Implement `judge.py`.** Build the agent with `agent_factory(model=build_model(judge), instructions=JUDGE_PROMPT, telemetry=False)`; the user message is `f"Pregunta del dueño:\n{question}\n\nRespuesta del asistente:\n{reply}"`. A completed run's `content` goes to `parse_verdict`; any other status is an error.
